<objective>
Implement safe config write operations and reconnect auto-refresh for the Settings screen.

Purpose: The current `saveConfig()` and `saveConfigToggle()` methods PUT the entire `ClaudeConfig` struct back to the server. This silently drops CLI-only fields (`hooks`, `env`, `permissions`, `statusLine`, `enabledPlugins`, `extraKnownMarketplaces`) that the iOS app reads but should never write. This is the highest-risk bug in the settings flow. Additionally, SettingsView lacks `onChange(of: appState.isConnected)` for reconnect scenarios, unlike HomeView and BrowserView which already have it.

Output: SettingsViewModel with a safe `saveWithPatch` method that loads fresh config, applies a single-field delta, and PUTs back the complete config. All existing save call sites migrated. SettingsView gains reconnect auto-refresh.
</objective>

<task type="auto">
  <name>Task 1: Replace config save methods with read-then-patch pattern</name>
  <files>ILSApp/ILSApp/ViewModels/SettingsViewModel.swift</files>
  <action>
Replace the dangerous full-struct-PUT save methods with a safe read-then-patch pattern.

1. Add a new `saveWithPatch(applying:)` method to SettingsViewModel:
   - Takes a closure `(inout ClaudeConfig) -> Void` that applies a single-field delta
   - Step 1: GET fresh config from server (`client.get("/config?scope=user")`)
   - Step 2: Apply the delta closure to the fresh config (mutates ONLY the intended field)
   - Step 3: PUT the FULL config back (preserving hooks, env, permissions, etc. from the server)
   - Step 4: Update local `config` property from PUT response
   - Returns optional error String (nil on success)
   - Uses `isSaving` flag with defer for cleanup
   - Uses `do/catch` (NOT `try?`) for error handling per project convention

2. Rewrite `saveConfig(model:colorScheme:)` to call `saveWithPatch`:
   ```swift
   func saveConfig(model: String, colorScheme: String) async -> String? {
       return await saveWithPatch { config in
           config.model = model
           if config.theme == nil {
               config.theme = ThemeConfig(colorScheme: colorScheme, accentColor: nil)
           } else {
               config.theme?.colorScheme = colorScheme
           }
       }
   }
   ```

3. Rewrite `saveConfigToggle(key:value:)` to call `saveWithPatch`:
   ```swift
   func saveConfigToggle(key: String, value: Bool) async -> String? {
       return await saveWithPatch { config in
           switch key {
           case "alwaysThinkingEnabled":
               config.alwaysThinkingEnabled = value
           case "includeCoAuthoredBy":
               config.includeCoAuthoredBy = value
           default:
               break // Unknown keys silently ignored; caller validates
           }
       }
   }
   ```

4. Keep the fire-and-forget wrappers (`updateModel`, `updateToggle`) unchanged -- they already call `saveConfig`/`saveConfigToggle` then `loadConfig()`.

CRITICAL: The delta closure must ONLY touch fields the iOS app is allowed to modify: `model`, `theme` (colorScheme, accentColor), `autoUpdatesChannel`, `alwaysThinkingEnabled`, `includeCoAuthoredBy`. The closure never touches `hooks`, `env`, `permissions`, `statusLine`, `enabledPlugins`, `extraKnownMarketplaces`, or `apiKeyStatus`. This is enforced by only exposing delta closures for allowlisted fields -- never create a delta that modifies dangerous fields.

Do NOT add a separate `sanitizedForWrite` function that creates a new ClaudeConfig with nil dangerous fields. That approach would ALSO drop server-side fields. The read-then-patch approach is correct because it loads the FULL config (including all CLI fields) and only mutates the one field the user changed.
