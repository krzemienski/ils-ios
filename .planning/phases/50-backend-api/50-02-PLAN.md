Fix the restart handler (around line 258-263) where `try?` silently swallows settings file read errors on a mutation path.

**Current code (lines ~258-263):**
```swift
var json: [String: Any] = [:]
if fm.fileExists(atPath: settingsPath),
   let data = try? Data(contentsOf: URL(fileURLWithPath: settingsPath)),
   let existing = try? JSONSerialization.jsonObject(with: data) as? [String: Any] {
    json = existing
}
```

**Replace with error-propagating version:**
```swift
var json: [String: Any] = [:]
if fm.fileExists(atPath: settingsPath) {
    let data: Data
    do {
        data = try Data(contentsOf: URL(fileURLWithPath: settingsPath))
    } catch {
        throw Abort(.internalServerError, reason: "Failed to read settings file: \(error.localizedDescription)")
    }
    guard let existing = try? JSONSerialization.jsonObject(with: data) as? [String: Any] else {
        throw Abort(.unprocessableEntity, reason: "Settings file contains invalid JSON")
    }
    json = existing
}
```

**Rationale:** The Data read failure (permissions, disk error) should return 500 since the subsequent write would overwrite the file with incomplete data. The JSON parse uses `try?` with a guard-else throwing 422, distinguishing "can't read file" (500) from "file isn't valid JSON" (422). If the file doesn't exist at all, we proceed with an empty dict (that's the expected path for first-time setup).

**DO NOT touch these other try? usages in MCPController (they are correct):**
- Line 147: `try? fileSystem.removeMCPServer(...)` -- delete-if-exists pattern
- Line 321: `try? fm.contentsOfDirectory(...)` -- log listing, best-effort
- Line 333: `try? String(contentsOfFile:...)` -- log content read, best-effort
