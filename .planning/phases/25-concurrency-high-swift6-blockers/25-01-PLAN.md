**TeamsExecutorService.swift — CONC-01 / SWIFT6-02:**

In `shutdownTeammate(teamName:memberName:)` (line ~89-116), the `Task.detached` closure on line 100 captures `process` (a Foundation.Process, which is NOT Sendable) across the actor isolation boundary. This is a Swift 6 compile-error blocker.

Fix:
1. Extract ALL needed Sendable values BEFORE the Task.detached boundary:
   - `let pid = process.processIdentifier` (Int32, Sendable) — already done on line 97
   - The `process.isRunning` check on line 104 also captures `process`. Replace with a `kill(pid, 0) == 0` check which only uses the Sendable `pid` value.
2. The Task.detached closure should capture ONLY `pid` (Int32). Remove all references to `process` inside the closure.

The corrected code for `shutdownTeammate` should look like:

```swift
func shutdownTeammate(teamName: String, memberName: String) {
    guard let process = activeProcesses[teamName]?[memberName] else {
        return
    }

    // Send SIGTERM
    process.terminate()

    // Extract Sendable value before crossing actor boundary
    let pid = process.processIdentifier

    // Spawn a detached task to send SIGKILL after 5 seconds if still running
    Task.detached {
        try? await Task.sleep(nanoseconds: 5_000_000_000)
        // Use kill(pid, 0) to check if process is still alive — avoids capturing non-Sendable Process
        if kill(pid, 0) == 0 {
            kill(pid, SIGKILL)
        }
    }

    // Remove from tracking
    activeProcesses[teamName]?.removeValue(forKey: memberName)

    // Clean up empty team entry
    if activeProcesses[teamName]?.isEmpty == true {
        activeProcesses.removeValue(forKey: teamName)
    }
}
```

**SystemMetricsService.swift — CONC-07:**

In `getProcesses()` (line ~83-127), `withCheckedContinuation` is used inside `DispatchQueue.global().async`. The timeout `DispatchWorkItem` on line 96-98 calls `process.terminate()` which could cause the normal path to also resume the continuation. Although there is no explicit double-resume in the current code (the timeout just terminates the process, causing `readDataToEndOfFile` to return empty), the risk is that if the timeout fires AFTER the continuation has already resumed, and there's a code path change in the future, it could double-resume.

Fix:
1. Add a `var hasResumed = false` flag inside the `DispatchQueue.global().async` block, BEFORE the continuation.
2. Guard every `continuation.resume(returning:)` call with `guard !hasResumed else { return }` then `hasResumed = true`.
3. This makes the pattern defensive — even if timeout and normal completion race, only the first resume executes.

The corrected `getProcesses` should wrap the continuation block like:

```swift
func getProcesses() async -> [SystemProcessInfo] {
    return await withCheckedContinuation { continuation in
        DispatchQueue.global(qos: .userInitiated).async {
            var hasResumed = false

            let process = Process()
            process.executableURL = URL(fileURLWithPath: "/bin/ps")
            process.arguments = ["aux"]

            let outPipe = Pipe()
            let errPipe = Pipe()
            process.standardOutput = outPipe
            process.standardError = errPipe

            // 5-second timeout: terminate the process if it hangs
            let timeoutItem = DispatchWorkItem {
                process.terminate()
                if !hasResumed {
                    hasResumed = true
                    continuation.resume(returning: [])
                }
            }
            DispatchQueue.global().asyncAfter(deadline: .now() + 5, execute: timeoutItem)

            do {
                try process.run()

                let data = outPipe.fileHandleForReading.readDataToEndOfFile()
                _ = errPipe.fileHandleForReading.readDataToEndOfFile()

                process.waitUntilExit()
                timeoutItem.cancel()

                guard !hasResumed else { return }
                hasResumed = true

                guard let output = String(data: data, encoding: .utf8) else {
                    continuation.resume(returning: [])
                    return
                }

                let results = Self.parseProcessOutputStatic(output)
                continuation.resume(returning: results)
            } catch {
                timeoutItem.cancel()
                guard !hasResumed else { return }
                hasResumed = true
                continuation.resume(returning: [])
            }
        }
    }
}
```

Key changes:
- `hasResumed` flag prevents double-resume
- Timeout handler now also resumes continuation (previously it just terminated — leaving continuation hanging if timeout fired during `readDataToEndOfFile`)
- Every resume site is guarded
