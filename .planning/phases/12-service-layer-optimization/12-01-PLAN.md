Add in-flight GET request coalescing and NSCache cost bounding to the existing APIClient actor. All changes are within the actor, so thread safety is guaranteed by actor isolation.

1. **Add in-flight dictionary property** (after the `cache` property, around line 15):
   ```swift
   /// In-flight GET tasks keyed by path. Actor isolation makes this thread-safe.
   /// Concurrent GET requests to the same path share a single network call.
   private var inFlightGETs: [String: Task<Any, Error>] = [:]
   ```

2. **Set totalCostLimit in init()** (after `cache.countLimit = 100` on line 57):
   ```swift
   cache.totalCostLimit = 10 * 1024 * 1024  // 10MB memory budget
   ```

3. **Add cost estimation helper** (as a private method on the actor):
   ```swift
   /// Approximate memory cost for NSCache eviction priority.
   /// Uses MemoryLayout.stride as a relative measure -- absolute accuracy
   /// is unnecessary since NSCache treats cost as a priority signal.
   private func estimatedCost<T>(for value: T) -> Int {
       let baseStride = MemoryLayout<T>.stride
       if let array = value as? any RandomAccessCollection {
           return max(baseStride, baseStride * array.count)
       }
       return baseStride
   }
   ```

4. **Modify the `get<T>()` method** to coalesce in-flight requests. After the existing cache check (which returns early on cache hit), add coalescing logic BEFORE the network call:
   - Check `inFlightGETs[path]` -- if a task exists, `try await` its value and cast to T. On type mismatch, fall through to a new request.
   - If no in-flight task, wrap the existing network+decode logic in a `Task<Any, Error>`, store it in `inFlightGETs[path]`, and use `defer { inFlightGETs[path] = nil }` at the top of the task body for cleanup on both success and failure.
   - When storing the decoded value in cache, use `cache.setObject(entry, forKey: cacheKey, cost: estimatedCost(for: decoded))` instead of the current cost-less `setObject`.

5. **Update `invalidateCacheForMutation()`** to also cancel and remove in-flight GETs for the affected path and its parent list path. This prevents a race where a POST invalidates cache but a concurrent GET re-populates it with stale data:
   ```swift
   inFlightGETs[path]?.cancel()
   inFlightGETs.removeValue(forKey: path)
   // Also cancel parent list path (existing parent-path logic)
   ```

**IMPORTANT constraints:**
- Only coalesce GET requests. POST/PUT/DELETE methods MUST NOT use the in-flight dictionary.
- Use `as?` (not `as!`) for the type cast from Any back to T. Fall through to a new request on mismatch.
- SSEClient is a completely separate class -- do not touch it.
- Preserve all existing cache TTL logic, retry logic, and API key handling unchanged.

  <name>Task 2: Add memory pressure observer for proactive cache eviction</name>
  <files>ILSApp/ILSApp/ILSAppApp.swift</files>
  <action>
Add a `UIApplication.didReceiveMemoryWarningNotification` observer to proactively evict caches when the system signals memory pressure. This supplements NSCache's built-in eviction (which handles the in-memory cache) by also clearing the GRDB-backed persistent CacheService.

1. **Add a stored property** for the notification observer token in the App struct or its associated state:
   ```swift
   #if os(iOS)
   private var memoryWarningObserver: NSObjectProtocol?
   #endif
   ```

2. **Register the observer** in the app's initialization or `.onAppear` of the root view. Use `NotificationCenter.default.addObserver(forName:object:queue:)`:
   ```swift
   #if os(iOS)
   memoryWarningObserver = NotificationCenter.default.addObserver(
       forName: UIApplication.didReceiveMemoryWarningNotification,
       object: nil,
       queue: .main
   ) { _ in
       Task {
           await CacheService.shared.cleanupExpired()
           AppLogger.shared.warning("Memory pressure: caches evicted", category: "memory")
       }
   }
   #endif
   ```

3. The `#if os(iOS)` guard is required because `UIApplication.didReceiveMemoryWarningNotification` does not exist on macOS. On macOS, NSCache's built-in eviction is sufficient.

**IMPORTANT constraints:**
- Do NOT create a new file (no MemoryPressureMonitor class). This is a single observer registration.
- Use `[weak self]` if capturing self; or if placed in a non-capturing closure (as shown), it is safe.
- CacheService.shared.cleanupExpired() already exists and handles GRDB cleanup.
- AppLogger.shared.warning() already exists for diagnostics.
