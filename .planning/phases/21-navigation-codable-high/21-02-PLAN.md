  CONTEXT: Swift's synthesized Codable for `String, RawRepresentable` enums silently returns `nil` on `init?(rawValue:)` for unknown strings, which at the Codable level means the entire containing struct fails to decode. This is better than crashing, but the error message is unhelpful ("The data couldn't be read because it isn't in the correct format"). Adding explicit `init(from:)` implementations that throw `DecodingError.dataCorrupted` with a human-readable message dramatically improves debuggability.

  IMPORTANT: `ClaudeModel` in Session.swift already handles this correctly via `unknown(_:)` associated value case. Do NOT touch it.

  The enums to fix:

  **Session.swift** — 3 enums:

  For each, add a custom `init(from decoder: Decoder) throws` after the enum cases. Pattern:
  ```swift
  public init(from decoder: Decoder) throws {
      let container = try decoder.singleValueContainer()
      let raw = try container.decode(String.self)
      guard let value = Self(rawValue: raw) else {
          throw DecodingError.dataCorrupted(
              DecodingError.Context(
                  codingPath: decoder.codingPath,
                  debugDescription: "Unrecognized \(Self.self) value: '\(raw)'. Expected one of: \(Self.allCases.map(\.rawValue).joined(separator: ", "))"
              )
          )
      }
      self = value
  }
  ```
