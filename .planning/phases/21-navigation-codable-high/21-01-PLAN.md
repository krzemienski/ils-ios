  <name>Task 2: Remove NavigationStack wrappers from sheet-presented views (NAV-02)</name>
  <files>
    ILSApp/ILSApp/Views/Sessions/SessionInfoView.swift
    ILSApp/ILSApp/Views/Sessions/NewSessionView.swift
    ILSApp/ILSApp/Views/Premium/PremiumView.swift

    ILSApp/ILSApp/Views/Chat/CommandPaletteView.swift
  </files>
  <action>
  CONTEXT: These views are always presented as .sheet() content. SidebarRootView.mainContent already wraps all screens in a NavigationStack. Presenting a sheet that itself contains a NavigationStack creates a nested NavigationStack, which Apple warns against in HIG and causes unpredictable navigation bar behavior.

  The fix: strip the NavigationStack { ... } wrapper from each view's body. The navigation title and toolbar modifiers should be moved DOWN onto the root content view inside the now-removed NavigationStack. This is the standard pattern — sheet-presented views get navigation chrome from modifiers on their root content, not from a wrapping NavigationStack.

  EXCEPTION: ServerSetupSheet intentionally has NavigationStack because it needs internal drill-down navigation (OnboardingView → QuickConnectView / SSHSetupView). Do NOT touch ServerSetupSheet. Similarly ThemeEditorView's NavigationStack is embedded in ThemesListView's .sheet — leave ThemesListView alone (those are standalone modal flows).

  FOR EACH FILE below, the change pattern is:

  **SessionInfoView.swift** (line 23):
  - The body is `NavigationStack { Group { ... } .navigationTitle(...) .toolbar { ... } }`
  - Remove `NavigationStack {` opener and its matching `}` closer
  - The `Group { ... }` with its `.navigationTitle` and `.toolbar` modifiers becomes the direct body
  - Keep `.sheet(isPresented: $showExportSheet)` which is on the outer view at line 123

  **NewSessionView.swift** (line 57):
  - The body is `NavigationStack { VStack(spacing: 0) { ... } .navigationTitle(...) .toolbar { ... } }`
  - Remove `NavigationStack {` and its matching `}`
  - The `VStack` with modifiers becomes the direct body

  **PremiumView.swift** (line 20):
  - The body is `NavigationStack { ScrollView { ... } .navigationTitle(...) .toolbar { ... } }`
  - Remove `NavigationStack {` and its matching `}`
  - The `ScrollView` with modifiers becomes the direct body

  **SpawnTeammateView.swift** (line 18):
  - The body is `NavigationStack { Form { ... } .navigationTitle(...) .toolbar { ... } }`
  - Remove `NavigationStack {` and its matching `}`
  - The `Form` with modifiers becomes the direct body

  **CreateTeamView.swift** (line 18):
  - The body is `NavigationStack { Form { ... } .navigationTitle(...) .toolbar { ... } }`
  - Remove `NavigationStack {` and its matching `}`
  - The `Form` with modifiers becomes the direct body

  **AdvancedOptionsSheet.swift** (line 62):
  - The body is `NavigationStack { Form { ... } .navigationTitle(...) .toolbar { ... } }`
  - Remove `NavigationStack {` and its matching `}`
  - The `Form` with modifiers becomes the direct body

  **CommandPaletteView.swift** (line 53):
  - The body is `NavigationStack { List { ... } .navigationTitle(...) .toolbar { ... } }`
  - Remove `NavigationStack {` and its matching `}`
  - The `List` with modifiers becomes the direct body

  IMPORTANT: After removing NavigationStack, the views need navigation chrome from the sheet context. Since sheets on iOS 16+ automatically get a navigation bar when they contain `.navigationTitle`, this works correctly. If `.navigationTitle` is already on the inner content view (which it is in all these cases — it's applied to the content, not to the NavigationStack itself), the sheet will still display correctly.

  ALSO: The #Preview wrappers at the bottom of some files wrap in `NavigationStack { ... }` for preview display — leave those alone, they are correct for previewing in isolation.
  </action>

  <name>Task 3: Add NavigationStack to MacContentView detail column and add hooks route (NAV-03, NAV-04)</name>
  <files>

  <action>
  CURRENT STATE (MacContentView.swift):

  1. `detailContent` (lines 309-338) is a bare `@ViewBuilder` returning screen views directly — no NavigationStack. This means macOS detail views have no navigation infrastructure, so `.navigationTitle` and `.toolbar` modifiers on child views have no NavigationBar to attach to.

  2. `SidebarSection` enum (lines 9-43) has no `.hooks` case, so the hooks screen is unreachable on macOS.

  3. `detailContent` (lines 309-338) has a `.hooks` case rendering `HooksManagementView()`, but the sidebar section enum does not include hooks, so it can never be activated via sidebar selection.

  4. `handleNavigationIntent` (lines 559-574) has a `case .hooks: selectedSection = .settings` mapping — hooks is remapped to settings rather than to its own section.

  CHANGE 1 — Add hooks to SidebarSection enum:
  After line 15 (`case themes = "Themes"`), add:
  ```swift
  case hooks = "Hooks"
  ```

  Add the icon for hooks in the `var icon: String` switch (after `case .themes: return "paintpalette.fill"`):
  ```swift
  case .hooks: return "bolt.fill"
  ```

  Add the screen mapping in `var screen: ActiveScreen` switch (after `case .themes: return .themes`):
  ```swift
  case .hooks: return .hooks
  ```

  CHANGE 2 — Fix handleNavigationIntent for hooks:
  In `handleNavigationIntent` (around line 569), change:
  FROM: `case .hooks: selectedSection = .settings  // hooks navigates from settings context`
  TO:   `case .hooks: selectedSection = .hooks`

  CHANGE 3 — Wrap detailContent in NavigationStack:
  The `detail:` closure in the NavigationSplitView (lines 71-75) currently is:
  ```swift
  } detail: {
      // Detail view (main content)
      detailContent
          .navigationSplitViewColumnWidth(min: 600, ideal: 800)
  }
  ```
  Change it to wrap detailContent in a NavigationStack:
  ```swift
  } detail: {
      // Detail view (main content)
      NavigationStack {
          detailContent
      }
      .navigationSplitViewColumnWidth(min: 600, ideal: 800)
  }
  ```

  NOTE: `.navigationSplitViewColumnWidth` must remain on the outer view (outside NavigationStack), not inside it, to correctly constrain the column width.
