  <action>
Create three performance test files in a new `PerformanceTests/` directory inside `ILSAppUITests/`:

**LaunchPerformanceTests.swift** (TEST-01):
- `import XCTest`
- `final class LaunchPerformanceTests: XCTestCase`
- `testColdLaunchPerformance()`: Use `measure(metrics: [XCTApplicationLaunchMetric()])` with `XCUIApplication().launch()` inside the closure. This measures from process start to first frame. Default 5 iterations + 1 warm-up.
- `testWarmLaunchPerformance()`: Use `XCTApplicationLaunchMetric(waitUntilResponsive: true)` (iOS 14+ guard) to measure until the app is interactive, not just first frame rendered.
- No backend dependency needed -- launch tests just measure app startup.

**MemoryPerformanceTests.swift** (TEST-02):
- `final class MemoryPerformanceTests: XCTestCase`
- `let app = XCUIApplication()`
- In `setUp()`: set `continueAfterFailure = false`, set `app.launchArguments = ["--uitesting"]`, set `app.launchEnvironment = ["BACKEND_URL": "http://localhost:9999"]`, call `app.launch()`.
- `testSessionBrowsingMemory()`: Wait for `app.collectionViews.firstMatch` or `app.tables.firstMatch` (whichever the sessions list uses) with 15s timeout. Then `measure(metrics: [XCTMemoryMetric(application: app)])` with a closure that does `swipeUp()`, `swipeUp()`, `swipeDown()` on the list to simulate browsing. XCTMemoryMetric captures physical footprint.
- Add a comment noting the known XCTMemoryMetric zero-value issue on some simulator configurations. If the first run shows 0 KB, the baseline should not be set -- MetricKit (Plan 02) provides the production fallback.

**ScrollPerformanceTests.swift** (TEST-03):
- `final class ScrollPerformanceTests: XCTestCase`
- `let app = XCUIApplication()`
- Same `setUp()` pattern as MemoryPerformanceTests (backend URL, --uitesting, launch).
- `testSessionsListScrollPerformance()`: Wait for the sessions list (collectionViews or tables). Create `XCTMeasureOptions()`, set `options.invocationOptions = [.manuallyStop]`. Call `measure(metrics: [XCTCPUMetric(application: app), XCTOSSignpostMetric.scrollingAndDecelerationMetric], options: options)` with a closure that does `swipeUp(velocity: .fast)`, then `stopMeasuring()`, then `swipeDown(velocity: .fast)` (reset outside measurement window).
- This captures both CPU usage during scroll and the hitch time ratio from the OS scroll signpost.

All three files should NOT subclass XCUITestBase -- performance tests need minimal setup overhead to avoid polluting measurements. Keep them as plain XCTestCase subclasses.

Ensure the new directory is inside ILSAppUITests/ so the existing `project.yml` source glob (`path: ILSAppUITests`) picks them up automatically.
