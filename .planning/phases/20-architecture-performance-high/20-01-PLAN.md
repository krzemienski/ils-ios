**NewSessionView (ARCH-06):**
`filteredRecentSessions` (line ~353) is a computed property filtering `recentSessions` by `forkSearchText`. Convert to @State cache:
1. Add `@State private var cachedFilteredSessions: [ChatSession] = []`
2. Add `.task(id: forkSearchText)` (or `.onChange(of: forkSearchText)`) that computes the filtered list and stores it. Include debounce via `try? await Task.sleep(for: .milliseconds(150))` before filtering.
3. Also trigger recomputation when `recentSessions` changes (use `.onChange(of: recentSessions.count)` or combine into a single task ID).
4. Replace all body references from `filteredRecentSessions` to `cachedFilteredSessions`.
5. Delete the old computed property.

**SidebarRootView (ARCH-07):**
Line ~122 constructs a Dictionary inline during `.task`:
```swift
let sessionIndex = Dictionary(uniqueKeysWithValues: sessionsVM.sessions.map { ($0.id, $0) })
```
This is already in a `.task` block (not in body), so it is not recomputed on every render. However, the intent of the audit finding is to avoid building a throwaway dictionary each time. Move this to a helper function on the ViewModel or on the sessions array extension. Specifically:
1. In `SessionsViewModel`, add a method `func session(byID id: UUID) -> ChatSession?` that does a simple `sessions.first(where: { $0.id == id })` — the sessions count is small (~50 DB sessions loaded at task time), so O(n) here is fine for a one-time lookup.
2. Replace the dictionary construction in SidebarRootView with `sessionsVM.session(byID: uuid)`.
3. Delete the dictionary construction line.
