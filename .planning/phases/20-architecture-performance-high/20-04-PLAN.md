**SessionsController sort optimization (SPERF-05):**
Currently line ~109: `merged.sort { $0.lastActiveAt > $1.lastActiveAt }` sorts the entire 22K+ array on every page request. This is O(n log n) where n can be 22K+.

Optimization approach — multiple strategies, pick the most practical:

**Strategy A (preferred): Partial sort / paginated extraction**
Since the caller only needs `limit` items (typically 50), use `partialSort` or a selection algorithm:
1. Instead of full `.sort()`, use a min-heap or partial sort to find the top `offset + limit` items.
2. Swift does not have a built-in partial sort, but we can use:
   ```swift
   // Only need the first (offset + limit) items sorted
   let needed = min(offset + limit, merged.count)
   // Use nthElement-style approach or just sort and take prefix
   ```
3. Actually, for the common case (page 1, limit 50), we only need the 50 most recent items.
4. Simplest practical improvement: if page==1 and no search filter, skip the full sort and use `max(count: limit)`:
   ```swift
   if offset == 0 && search == nil {
       // Fast path: find top `limit` items without full sort
       let topItems = merged.sorted(by: { $0.lastActiveAt > $1.lastActiveAt }).prefix(limit)
       // Still O(n log n) but we can optimize further
   }
   ```

**Strategy B: Pre-sort external sessions on load**
The external sessions list is loaded from a cached file scan. Sort them once at cache time (in FileSystemService) rather than on every request. Then merge two pre-sorted arrays:
1. In `FileSystemService.listExternalSessionsAsChatSessions()`, sort the result by `lastActiveAt` descending before caching.
2. In SessionsController, DB sessions are also pre-sorted by query (add `.sort(\.$updatedAt, .descending)` to the Fluent query).
3. Merge two pre-sorted arrays into one sorted array in O(n) using merge from merge-sort.
4. This is the most impactful optimization — sort once at cache time, merge at request time.

**Implementation (Strategy B):**
1. Add `.sort(\.$updatedAt, .descending)` to the `dbQuery` in SessionsController (line ~68).
2. In FileSystemService, find `listExternalSessionsAsChatSessions()` and add `.sorted(by: { $0.lastActiveAt > $1.lastActiveAt })` to the cached result.
3. In SessionsController.list(), replace `merged.sort { ... }` with a merge of two pre-sorted arrays:
   ```swift
   // Both dbSessions and externalSessions are pre-sorted by lastActiveAt descending
   // Simple merge: since we only need the first (offset + limit) items,
   // we can stop merging early
   var result: [ChatSession] = []
   result.reserveCapacity(min(offset + limit, merged.count))
   var i = 0, j = 0
   let dbArr = dbSessions.map { ... } // already sorted from query
   let extArr = uniqueExternal // already sorted from cache
   while result.count < offset + limit && (i < dbArr.count || j < extArr.count) {
       if i >= dbArr.count { result.append(extArr[j]); j += 1 }
       else if j >= extArr.count { result.append(dbArr[i]); i += 1 }
       else if dbArr[i].lastActiveAt > extArr[j].lastActiveAt { result.append(dbArr[i]); i += 1 }
       else { result.append(extArr[j]); j += 1 }
   }
   ```
4. If the merge approach adds too much complexity, the simpler fix is just adding the Fluent `.sort()` and documenting that the external sessions cache is pre-sorted. The full `merged.sort` remains but is documented as a known cost.
5. **Minimum viable fix**: Add the Fluent `.sort()` to DB query. For the combined sort, note that `merged.sort` is called after search/filter — if a search filter reduces the set significantly, the sort cost drops. Add a comment: `// TODO: Pre-sort external sessions at cache time for O(n) merge`.
