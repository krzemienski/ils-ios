**MEM-02 — NSWindow delegate cycle:**
In `WindowFrameDelegate` (line 224-264), the `windowManager` property is already declared as `weak var windowManager: WindowManager?` on line 226. This is correct — the delegate does NOT create a retain cycle because:
1. `WindowManager` holds `windowDelegates: [UUID: WindowFrameDelegate]` (strong)
2. `WindowFrameDelegate` holds `weak var windowManager: WindowManager?` (weak)
3. `NSWindow.delegate` is a `weak` property in AppKit

However, there IS a potential issue: when `window.delegate = delegate` is set in `setupWindowPersistence` (line 154), the window holds a weak ref to the delegate. But the delegate is stored in `windowDelegates` dict (strong), so it stays alive. When `unregisterWindow` removes from `windowDelegates`, the delegate is deallocated, and the window's weak delegate becomes nil. This is correct behavior.

Verify and document: Above the `WindowFrameDelegate` class declaration, add:
```swift
/// MEM-02: No retain cycle exists. WindowManager -> WindowFrameDelegate (strong via windowDelegates dict).
/// WindowFrameDelegate -> WindowManager (weak). NSWindow -> delegate (weak, per AppKit convention).
/// Delegate is deallocated when unregisterWindow removes it from windowDelegates.
```

**TeamsExecutorService.swift (MEM-06) — NSTask held 5s post-termination:**
In `shutdownTeammate` (lines 89-116), the `Task.detached` closure on line 100-107 captures `process` (the Process/NSTask object) and holds it for up to 5 seconds after termination. The `process` reference is already removed from `activeProcesses` on line 110, but the detached Task still holds a strong reference.

Fix: Extract only the `pid` before the detached task and use `kill()` with the pid instead of holding the Process reference:

```swift
func shutdownTeammate(teamName: String, memberName: String) {
    guard let process = activeProcesses[teamName]?[memberName] else {
        return
    }

    // Send SIGTERM
    process.terminate()

    // MEM-06: Extract pid and release Process reference. The detached task
    // only needs the pid for SIGKILL fallback, not the full NSTask object.
    let pid = process.processIdentifier
    let isStillRunning = process.isRunning

    // Remove from tracking immediately (releases our strong ref to Process)
    activeProcesses[teamName]?.removeValue(forKey: memberName)
    if activeProcesses[teamName]?.isEmpty == true {
        activeProcesses.removeValue(forKey: teamName)
    }

    // Only spawn SIGKILL fallback if process was still running after SIGTERM
    guard isStillRunning else { return }

    // MEM-07: Detached task only captures Sendable pid (Int32), not the Process object.
    // 5s timeout is acceptable — it's a fallback for processes that ignore SIGTERM.
    Task.detached {
        try? await Task.sleep(nanoseconds: 5_000_000_000)
        // Check if process is still alive via kill(pid, 0) signal probe
        if kill(pid, 0) == 0 {
            kill(pid, SIGKILL)
        }
    }
}
```

Key changes:
1. Process reference is released when removed from `activeProcesses` (before the 5s sleep)
2. Detached task captures only `pid` (Int32, Sendable) not `process` (NSTask, non-Sendable)
3. Uses `kill(pid, 0)` to probe if process is still alive instead of `process.isRunning`
4. This also fixes the non-Sendable Process crossing actor boundary issue from the audit
