**NotificationManager.swift:**

The class is `@MainActor` and conforms to `@preconcurrency UNUserNotificationCenterDelegate`. The delegate methods (`willPresent` and `didReceive`) are called by the system on an arbitrary thread, but since the class is `@MainActor`, the protocol conformance needs to be on `@MainActor` too.

Fix: Remove `@preconcurrency` and add `@MainActor` to the extension explicitly. The UNUserNotificationCenterDelegate methods will be dispatched to the MainActor automatically when the conformance is @MainActor.

Change line 151:
```swift
// FROM:
extension NotificationManager: @preconcurrency UNUserNotificationCenterDelegate {

// TO:
extension NotificationManager: UNUserNotificationCenterDelegate {
```

Since `NotificationManager` is already `@MainActor`, the extension inherits that isolation. The delegate methods will be called on MainActor. The `completionHandler` calls within are fine since they're just calling a closure (no isolation issue).

**Important:** The `completionHandler` parameter types use `@escaping` which is fine — completion handlers in delegate methods are expected to be called synchronously within the method. If the compiler requires `@Sendable` annotation on the completion handler, that's a protocol requirement issue — in that case, keep the method signatures matching the protocol exactly.

If the compiler still complains because UNUserNotificationCenterDelegate is not declared as @MainActor in the SDK, then use `nonisolated` on each delegate method and hop to MainActor inside:

```swift
extension NotificationManager: UNUserNotificationCenterDelegate {
    nonisolated func userNotificationCenter(
        _ center: UNUserNotificationCenter,
        willPresent notification: UNNotification,
        withCompletionHandler completionHandler: @escaping (UNNotificationPresentationOptions) -> Void
    ) {
        completionHandler([])
    }

    nonisolated func userNotificationCenter(
        _ center: UNUserNotificationCenter,
        didReceive response: UNNotificationResponse,
        withCompletionHandler completionHandler: @escaping () -> Void
    ) {
        let userInfo = response.notification.request.content.userInfo
        if let sessionIdString = userInfo["sessionId"] as? String,
           let sessionId = UUID(uuidString: sessionIdString) {
            Task { @MainActor in
                NotificationCenter.default.post(
                    name: NSNotification.Name("OpenSessionFromNotification"),
                    object: sessionId
                )
                NSApplication.shared.activate(ignoringOtherApps: true)
            }
        }
        completionHandler()
    }
}
```

The `willPresent` method doesn't access any @MainActor state (just calls completionHandler), so `nonisolated` is clean. The `didReceive` method needs @MainActor for `NSApplication.shared` and `NotificationCenter.default.post`, so wrap that part in `Task { @MainActor in }`. Call `completionHandler()` synchronously before the Task since it just signals the system.

class WindowFrameDelegate: NSObject, NSWindowDelegate {
    let sessionId: UUID
    weak var windowManager: WindowManager?
    private var debounceTask: Task<Void, Never>?

    init(sessionId: UUID, windowManager: WindowManager) {
        self.sessionId = sessionId
        self.windowManager = windowManager
        super.init()
    }

    deinit {
        debounceTask?.cancel()
    }

    func windowDidResize(_ notification: Notification) {
        guard let window = notification.object as? NSWindow else { return }
        debounceSave(window: window)
    }

    func windowDidMove(_ notification: Notification) {
        guard let window = notification.object as? NSWindow else { return }
        debounceSave(window: window)
    }

    func windowWillClose(_ notification: Notification) {
        debounceTask?.cancel()
        debounceTask = nil
    }

        debounceTask?.cancel()

        let manager = self.windowManager

            try? await Task.sleep(for: .milliseconds(500))

        }
    }
