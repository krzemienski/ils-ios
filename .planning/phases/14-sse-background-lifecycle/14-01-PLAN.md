**Extend the existing `onChange(of: scenePhase)` handler in SystemMonitorView** to disconnect the WebSocket on background and reconnect on foreground.

Current code:
```swift
.onChange(of: scenePhase) { _, phase in
    if phase == .active {
        if viewModel.isConnected {
            livePulse = true
        }
    } else {
        livePulse = false
    }
}
```

Replace with:
```swift
.onChange(of: scenePhase) { _, phase in
    switch phase {
    case .active:
        viewModel.connect()  // BATT-02: Resume WebSocket on foreground
        if viewModel.isConnected { livePulse = true }
    case .background:
        viewModel.disconnect()  // BATT-02: Suspend WebSocket on background
        livePulse = false
    default:
        livePulse = false
    }
}
```

**Key safeguards** (already in place -- verify, do not add):
- `MetricsWebSocketClient.connect()` has `guard webSocketTask == nil, pollingTask == nil else { return }` which prevents double-connect if both `onAppear` and `scenePhase == .active` fire.
- `MetricsWebSocketClient.disconnect()` safely cancels all tasks and resets state.

**Do NOT:**
- Disconnect on `.inactive` -- that fires for transient events like notification center pull-down (Pitfall 1 from research)
- Add a separate `NotificationCenter` observer in MetricsWebSocketClient -- use the view-level scenePhase handler since the view already owns the connection lifecycle (onAppear/onDisappear)
- Touch `ILSAppApp.swift` or `AppState.handleScenePhase()` -- MetricsWebSocketClient is owned by the view, not AppState
