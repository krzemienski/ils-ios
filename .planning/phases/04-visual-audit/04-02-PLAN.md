    First, grep the ENTIRE codebase for ALL `withAnimation` calls:
    ```
    grep -rn 'withAnimation' ILSApp/ --include='*.swift'
    ```
    Save output to `/tmp/ils-audit-evidence/phase4/reduce-motion-audit.txt`.

    For EACH `withAnimation` call found, check if it is gated on `accessibilityReduceMotion`. The correct pattern is:
    ```swift
    @Environment(\.accessibilityReduceMotion) private var reduceMotion
    // ...
    if reduceMotion {
        // Apply change without animation
        property = newValue
    } else {
        withAnimation(.easeInOut(duration: 0.3)) {
            property = newValue
        }
    }
    ```
    Or the shorter pattern:
    ```swift
    withAnimation(reduceMotion ? nil : .easeInOut(duration: 0.3)) {
        property = newValue
    }
    ```

    Known violations to fix:
    1. **C1 — ILSAppApp.swift:56**: Launch animation. Read the file, find the `withAnimation` call near line 56, add `@Environment(\.accessibilityReduceMotion)` and gate the animation.
    2. **C2 — ProgressRing.swift:44**: Ring rotation animation. Read the file, add reduce motion gate. If `reduceMotion`, show static ring at final position instead of animating.
    3. **C3 — StatCard.swift:59**: Press scale animation. Read the file, add reduce motion gate. If `reduceMotion`, skip the `.scaleEffect` animation.
    4. **H12 — ScreenshotProtectionModifier.swift**: Animation without reduce motion check. Read the file, add gate.

    Fix ALL other ungated `withAnimation` calls found in the grep. Every single one must either:
    - Be gated on `reduceMotion`
    - Use `withAnimation(reduceMotion ? nil : .default)` pattern
    - Be a non-visual animation (e.g., data change) that is genuinely not affected by reduce motion (document why)

    After fixing, re-grep to verify zero ungated animations remain. Append the "after" grep to the audit file.

    **iPad UIScreen Fix (C4):**
    Read `UserMessageCard.swift`. Find `UIScreen.main.bounds` at approximately line 15.
    Replace with `containerRelativeFrame(.horizontal)` modifier or `GeometryReader` to get the actual container width.
    The correct fix for iOS 17+:
    ```swift
    .containerRelativeFrame(.horizontal) { width, _ in
        width * 0.85  // or whatever fraction of container width is needed
    }
    ```
    This respects iPad Split View and Slide Over layouts where `UIScreen.main.bounds` returns the FULL screen width, not the split pane width.
