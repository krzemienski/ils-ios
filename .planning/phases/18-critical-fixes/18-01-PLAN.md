<task type="auto">
  <name>Task 1: Convert AppLogger from @unchecked Sendable to OSAllocatedUnfairLock</name>
  <files>ILSApp/ILSApp/Services/AppLogger.swift</files>
  <action>
Replace the @unchecked Sendable conformance on AppLogger with proper thread-safe state management using OSAllocatedUnfairLock:

1. Remove `@unchecked Sendable` and make AppLogger `final class AppLogger: Sendable`
2. Create a private `BufferState: Sendable` struct holding the mutable `buffer: [String]` array
3. Replace the DispatchQueue-protected buffer with `private let state = OSAllocatedUnfairLock(initialState: BufferState())`
4. Update all buffer access to use `state.withLock { s in ... }` -- I/O (writeEntriesToDisk) must happen OUTSIDE the lock
5. Store the flush timer Task in a separate `OSAllocatedUnfairLock<Task<Void, Never>?>` for clean deinit cancellation
6. Ensure `enqueueEntry()` drains the buffer inside the lock, writes to disk outside the lock (buffer-full-flush pattern)

Do NOT convert to actor -- AppLogger is called synchronously from many contexts that cannot await.
  </action>
  <verify>

Build macOS: `xcodebuild -project ILSApp/ILSApp.xcodeproj -scheme ILSMacApp -destination 'platform=macOS' -quiet 2>&1 | tail -5`
Grep confirms: zero `@unchecked Sendable` in AppLogger.swift, zero `nonisolated(unsafe)` in AppLogger.swift, zero `DispatchQueue` for buffer in AppLogger.swift.
  </verify>
  <done>AppLogger compiles as Sendable (not @unchecked) with all mutable state protected by OSAllocatedUnfairLock. Both iOS and macOS builds pass.</done>
</task>

**SyntaxHighlighter.swift:**

2. Remove any `nonisolated(unsafe)` from the `highlighterCache` static var
3. The cache is now safe because the entire enum is MainActor-isolated -- all callers are SwiftUI views already on MainActor

**CodeBlockView.swift:**
1. Add `@State private var highlightedCode: AttributedString?` property
2. In the body, use `Text(highlightedCode ?? AttributedString(code))` as plain text fallback while async highlighting computes
3. Add `.task(id: code)` modifier that calls `SyntaxHighlighter.highlight(code:language:)` and assigns the result to `highlightedCode`
4. This prevents re-tokenization on every body evaluation -- highlighting only re-runs when the `code` value changes

All call sites of SyntaxHighlighter are SwiftUI views inside .task(id:) which runs on MainActor, so the @MainActor constraint is satisfied without requiring await.
