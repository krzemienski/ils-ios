<task type="auto">
  <name>Task 1: Convert AppLogger from @unchecked Sendable to OSAllocatedUnfairLock</name>
  <files>ILSApp/ILSApp/Services/AppLogger.swift</files>
  <action>
Replace the `@unchecked Sendable` conformance and DispatchQueue-based buffer protection with `OSAllocatedUnfairLock`:

1. Remove `@unchecked Sendable` from the class declaration. Make AppLogger a plain `final class` that is `Sendable` via its internal locking.
2. Import `os` (for `OSAllocatedUnfairLock`, available iOS 16+).
3. Replace `private var buffer: [String] = []` and `private let bufferQueue = DispatchQueue(...)` with:
   ```swift
   private let state = OSAllocatedUnfairLock(initialState: BufferState())

   private struct BufferState {
       var buffer: [String] = []
   }
   ```
4. Update `enqueueEntry` to use `state.withLock { $0.buffer.append(entry) }` and check count inside the lock. If count >= maxBufferSize, copy entries and clear buffer inside the lock, then flush outside the lock.
5. Update `flushBuffer()` — it is called from the timer and from `enqueueEntry`. Make it take entries as a parameter (flushed outside the lock) OR have it acquire the lock itself. The key rule: file I/O must happen OUTSIDE the lock to avoid blocking.
6. For the `flushTimer`, replace `DispatchSourceTimer` with a `Task` that loops with `try? await Task.sleep(for: .seconds(flushInterval))`. Store the Task in a `nonisolated(unsafe)` property (acceptable for Task cancel-only pattern in deinit), or store it in the locked state.
7. For `recentLogs()`: remove the `withCheckedContinuation` + `bufferQueue.async` pattern. Instead, flush via the lock, then read the file.
8. The `analyticsOptedIn` computed property accessing UserDefaults is fine — UserDefaults is thread-safe for reads.
9. Make AppLogger conform to `Sendable` explicitly (not @unchecked): `final class AppLogger: Sendable`. This works because all stored properties are either `let`, `Sendable`, or protected by `OSAllocatedUnfairLock`.

IMPORTANT: Do NOT use `actor` here — AppLogger is called synchronously from logging callsites that cannot await. OSAllocatedUnfairLock gives synchronous thread-safe access.
  </action>

  <action>
**SyntaxHighlighter.swift:**
1. Add `@MainActor` to the `enum SyntaxHighlighter` declaration (line 6).
2. Remove `nonisolated(unsafe)` from `highlighterCache` (line 14). It becomes a normal `private static var` since the entire enum is @MainActor.
3. Remove the misleading safety comment above `highlighterCache`.
4. The `highlight()` function remains `static` — it is now implicitly @MainActor.
5. All Grammar structs below are private value types (structs conforming to Grammar protocol) — they do NOT need @MainActor since they are stateless and only used within the @MainActor-isolated `highlight()` call.

**CodeBlockView.swift:**
1. Add a `@State` property to cache the highlighted result:
   ```swift
   @State private var highlightedCode: AttributedString?
   ```
2. Remove the inline `SyntaxHighlighter.highlight()` call from the view body (line 156). Replace with:
   ```swift
   Text(highlightedCode ?? AttributedString(displayedLines.joined(separator: "\n")))
   ```
   This shows plain text as fallback while highlighting loads.
3. Add `.task(id: code)` modifier on the code content VStack (or on the Text itself) that computes highlighting asynchronously:
   ```swift
   .task(id: code) {
       highlightedCode = SyntaxHighlighter.highlight(
           code: displayedLines.joined(separator: "\n"),
           language: language
       )
   }
   ```
   Using `code` as the task ID means highlighting re-runs only when the code content changes, NOT on every body evaluation.
4. Also cache the computed properties `codeLines`, `shouldBeCollapsible`, and `displayedLines` if feasible — but these are lightweight string splits, so the critical fix is the highlighting cache. The cascading computed properties (`codeLines` -> `shouldBeCollapsible` -> `displayedLines`) do string splits on every body eval but are O(n) on line count, not O(n) regex tokenization. Address only if build allows clean refactoring without bloating the diff.

NOTE: `.task(id:)` runs on the MainActor by default in SwiftUI, which is correct since SyntaxHighlighter is now @MainActor. The key benefit is that it runs ONCE per code change, not on every body re-evaluation.
