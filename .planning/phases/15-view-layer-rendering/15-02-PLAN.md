<objective>
Optimize the two largest lists in the app: sessions sidebar (500+ items) and chat messages (200+ messages).

Purpose: SidebarView uses `ScrollView { LazyVStack }` which creates views lazily but never recycles them — memory grows linearly with 500+ sessions. Migrating to `List` (UICollectionView-backed since iOS 16) provides view recycling and constant memory. ChatMessageList uses `ForEach(Array(messages.enumerated()))` which copies the entire array every body evaluation and destroys view identity. Fixing to stable identity and adding message windowing in ChatViewModel caps rendered messages at ~50.

Output: List-based sidebar with view recycling; windowed chat messages with stable ForEach identity.
</objective>

Fix the ForEach identity anti-pattern and add message windowing to cap rendered messages.

**Part A — ChatViewModel windowing (ChatViewModel.swift):**

1. Add a display window size constant and computed properties:
   ```swift
   private let displayWindowSize = 50

   /// Windowed messages for display — shows the most recent messages up to displayWindowSize.
   /// For small conversations, returns all messages.
   var displayMessages: [ChatMessage] {
       if messages.count <= displayWindowSize {
           return messages
       }
       return Array(messages.suffix(displayWindowSize))
   }

   /// Whether older messages exist beyond the current display window.
   var hasOlderMessages: Bool {
       messages.count > displayWindowSize
   }

   /// Get the previous message before the given message in the full messages array.
   /// Used for same-sender grouping in ChatMessageList.
   func previousMessage(before message: ChatMessage) -> ChatMessage? {
       guard let index = messages.firstIndex(where: { $0.id == message.id }),
             index > 0 else {
           return nil
       }
       return messages[index - 1]
   }
   ```

**Part B — ChatMessageList identity fix (ChatMessageList.swift):**

1. The `messages` let property stays as-is (it is passed from ChatView).

2. Replace the `messagesContent` body (around lines 118-157). Change:
   ```swift
   ForEach(Array(messages.enumerated()), id: \.element.id) { index, message in
       let prevMessage: ChatMessage? = index > 0 ? messages[index - 1] : nil
       let isSameSender = prevMessage?.isUser == message.isUser
       // ...
   }
   ```
   To:
   ```swift
   ForEach(messages) { message in
       let prevMessage: ChatMessage? = {
           guard let idx = messages.firstIndex(where: { $0.id == message.id }),
                 idx > 0 else { return nil }
           return messages[idx - 1]
       }()
       let isSameSender = prevMessage?.isUser == message.isUser

       if message.isUser {
           UserMessageCard(
               message: message,
               onDelete: onDeleteMessage
           )
           .padding(.horizontal, 16)
           .padding(.top, isSameSender ? 8 : 24)
       } else {
           AssistantCard(
               message: message,
               onRetry: { msg in
                   onRetryMessage(msg)
               },
               onDelete: onDeleteMessage
           )
           .padding(.horizontal, 16)
           .padding(.top, isSameSender ? 8 : 24)
       }
   }
   ```

   This eliminates the `Array(messages.enumerated())` copy on every body evaluation. ChatMessage is `Identifiable` so `ForEach(messages)` uses stable IDs.

   **Alternative (preferred if performance matters for previousMessage lookup):** Since the lookup is O(n) per message, and we have at most 50 windowed messages, the cost is O(n^2) with n=50 which is 2500 comparisons — negligible. But if desired, build a lookup dictionary:

   ```swift
   // At the top of messagesContent
   let prevMessageMap: [String: ChatMessage] = {
       var map = [String: ChatMessage]()
       for i in 1..<messages.count {
           map[messages[i].id] = messages[i-1]
       }
       return map
   }()
   ```
   Then use `prevMessageMap[message.id]` instead of the firstIndex lookup. Choose whichever approach is simpler.
