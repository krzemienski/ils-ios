<objective>
Move syntax highlighting computation off the main thread so code blocks with 100+ lines do not cause frame drops during scrolling or initial render.

Purpose: SyntaxHighlighter is currently `@MainActor`, so `.task(id:)` in CodeBlockView runs highlighting on the main thread. For large code blocks this blocks the UI. Replacing `@MainActor` isolation with `OSAllocatedUnfairLock` for the highlighter cache (same pattern as AppLogger from Phase 18) enables `Task.detached` to run highlighting on a background thread while maintaining cache thread safety.

Output: SyntaxHighlighter with nonisolated API and lock-protected cache; CodeBlockView using `Task.detached(priority: .userInitiated)` for all highlighting calls.
</objective>

2. Add `import os` at the top (for OSAllocatedUnfairLock).
3. Replace `private static var highlighterCache: [String: Splash.SyntaxHighlighter<AttributedStringOutputFormat>] = [:]` with:

   ```swift
       initialState: [String: Splash.SyntaxHighlighter<AttributedStringOutputFormat>]()
   )
   ```
4. Update the `highlight(code:language:)` method to use `cacheLock.withLock` for cache lookup and insertion. Get the highlighter instance under the lock, then call `highlighter.highlight(code)` OUTSIDE the lock (the actual highlighting is the expensive part and should not hold the lock):
   ```swift
   static func highlight(code: String, language: String?) -> AttributedString {
       guard let language = language?.lowercased() else {
           return plainMonospace(code)
       }
       let highlighter = cacheLock.withLock { cache -> Splash.SyntaxHighlighter<AttributedStringOutputFormat> in
           if let cached = cache[language] {
               return cached
           }
           let grammar = grammarForLanguage(language)
           let h = Splash.SyntaxHighlighter(format: outputFormat, grammar: grammar)
           cache[language] = h
           return h
       }
       return highlighter.highlight(code)
   }
   ```
5. `grammarForLanguage`, `plainMonospace`, `outputFormat` stay as-is — they are all stateless or value types.

This is the same OSAllocatedUnfairLock pattern used for AppLogger in Phase 18 (CONC-01). The lock protects only the cache lookup (microseconds); the actual highlighting runs without holding the lock.

Do NOT make SyntaxHighlighter an actor — that would require `await` at all call sites including synchronous `onChange` handlers.

Update CodeBlockView to call SyntaxHighlighter.highlight() via `Task.detached(priority: .userInitiated)` instead of directly on the main thread.

1. In the `.task(id: code)` modifier (around line 167-180), wrap the highlight call:
   ```swift
   .task(id: code) {
       let lines = code.components(separatedBy: .newlines)
       cachedCodeLines = lines
       cachedShouldBeCollapsible = lines.count > 10
       if cachedShouldBeCollapsible && !isExpanded {
           cachedDisplayedLines = Array(lines.prefix(collapsedLineLimit))
       } else {
           cachedDisplayedLines = lines
       }
       // Move highlighting off main thread
       let codeToHighlight = cachedDisplayedLines.joined(separator: "\n")
       let lang = language
       highlightedCode = await Task.detached(priority: .userInitiated) {
           SyntaxHighlighter.highlight(code: codeToHighlight, language: lang)
       }.value
   }
   ```
   Note: `codeToHighlight` and `lang` are captured as local let values (Sendable String types) before entering the detached task. The `await .value` returns the result back to the main actor where it is assigned to `@State highlightedCode`.

2. In the `.onChange(of: isExpanded)` handler (around line 181-191), apply the same pattern:

   ```swift
   .onChange(of: isExpanded) { _, expanded in

       } else {

   ```
