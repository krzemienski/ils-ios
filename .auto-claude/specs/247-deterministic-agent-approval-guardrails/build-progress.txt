Key Architecture Decisions:
- ApprovalPolicy sits ABOVE AutoApproveRule — policies define high-level guardrails, auto-approve rules handle granular tool-specific matching
- PolicyEvaluationService is deterministic: same inputs always produce same outputs
- Built-in templates (Strict/Balanced/Permissive) provide one-tap onboarding
- Reason codes are shared enums so backend and iOS display consistent information
- Auto-checkpoints before high-risk approvals leverage existing CheckpointViewModel infrastructure
- All policy-driven decisions are logged to audit trail for compliance
